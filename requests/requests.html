Requête 1e :

Quels fournisseurs proposent de la viande et du poisson ?

Notre réflexion

L'intérêt de cette requête est de trouver facilement les fournisseurs qui proposent deux types de protéines animales : le poisson et la viande. Ainsi, si KDou manque de poisson ou de viande, elle peut facilement en commander auprès de ces fournisseurs.

Ce qu'on a fait

Pour réaliser cette requête, nous avons sélectionné la table Fournisseur, puis créé deux sous-requêtes. Pour la première sous-requête, nous faisons une jointure entre les tables Produit et Catégorie. Puis, nous utilisons LIKE pour sélectionner uniquement les produits dont le nom de catégorie contient un mot similaire à « poisson ». Nous devons procéder ainsi, car les noms des catégories peuvent contenir d'autres mots que celui recherché. Pour éviter d'obtenir de faux résultats, nous devons donc utiliser LIKE. La deuxième sous-requête fait la même chose pour les produits de la catégorie « Viandes », avec LIKE "*Viande*". Enfin, nous avons trié les résultats par numéro de fournisseur et affiché toutes les colonnes de la table Fournisseur. Nous avons ainsi facilement les coordonnées des fournisseurs auprès desquels passer commande. 

SELECT
    F.*
FROM Fournisseur AS F
WHERE F.NoFour IN (
        SELECT P.NoFour
        FROM Produit AS P
            INNER JOIN Categorie ON Categorie.CodeCateg = P.CodeCateg
        WHERE Categorie.NomCateg LIKE "*Poisson*")
    AND F.NoFour IN (
        SELECT P.NoFour
        FROM Produit AS P
            INNER JOIN Categorie ON Categorie.CodeCateg = P.CodeCateg
        WHERE Categorie.NomCateg LIKE "*Viande*" )
ORDER BY
    F.NoFour;

Requête 1h :

Quels fournisseurs ne proposent que des desserts ?

Notre réflexion

L'intérêt de cette requête est de repérer les fournisseurs qui ne vendent que des desserts, car ces produits peuvent avoir un impact sur la santé des clients. Ainsi, si KDou sait quels fournisseurs ne proposent que des produits potentiellement nocifs pour la santé de ses clients, elle peut revoir ses partenariats avec eux. Cela donnerait une image plus positive de l'entreprise.

Ce qu'on a fait

Pour réaliser cette requête, nous avons utilisé la table Fournisseur et créé deux sous-requêtes. La première repère les fournisseurs qui proposent des produits n'appartenant pas à la catégorie « Desserts ». Cela est réalisé grâce à la jointure entre les tables Produit et Catégorie. Puis, nous sélectionnons avec NOT IN les produits qui ne sont pas de la catégorie « Desserts ». Ainsi, nous excluons les fournisseurs qui proposent des produits d'autres catégories. La deuxième sous-requête sélectionne les fournisseurs restants avec IN, à partir d'une jointure entre les tables Produit et Catégorie. Nous récupérons ainsi uniquement les entreprises qui vendent des desserts. Enfin, nous avons trié les résultats par société et affiché le nom, le numéro et la ville du fournisseur afin de pouvoir identifier plus facilement les entreprises. 

SELECT
    F.Societe,
    F.NoFour,
    F.Ville
FROM
    FournisseurAS F
WHERE
    F.NoFour NOT IN (
        SELECT
            P.NoFour
        FROM
            Categorie AS C
            INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
        WHERE
            C.NomCateg NOT LIKE "Desserts"
    )
   AND F.NoFour IN (
        SELECT
            P.NoFour
        FROM
            INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
    )
ORDER BY
    F.Societe;

Requête 2 :

Dans le cadre d'une réflexion sur l'origine des produits, nous voulons connaître le chiffre d'affaires total généré à ce jour par les fournisseurs de l'Union européenne.

Notre réflexion

L'intérêt d'analyser le CA des produits issus de fournisseurs de l'UE est de repérer les produits les plus rentables pour KDou. Cela permet également d'identifier les fournisseurs avec lesquels maintenir de bonnes relations et ceux avec qui des ajustements sont nécessaires.

Ce qu'on a fait

Pour réaliser cette requête,nous avons joint les tables Catégorie, Produit, Fournisseur, DétailCommande et Pays. Nous avons sélectionné les fournisseurs qui viennent d'un pays membre de l'Union européenne, puis nous avons regroupé les résultats par fournisseur, produit et pays. Nous avons ensuite trié les résultats par chiffre d'affaires décroissant. Nous avons décidé d'afficher la société du fournisseur, le nom du produit, le pays, le chiffre d'affaires et la marge. Le chiffre d'affaires est calculé à partir des quantités vendues, du coût d'achat, du coefficient de marge et de la remise grâce à la commande SUM et ROUND. La marge est calculée en soustrayant le coût d'achat des produits de leur prix de vente. Ces résultats permettent de repérer les produits les plus vendus et d'examiner leur marge afin de voir facilement lesquels sont rentables. L'affichage des fournisseurs permet également de connaître l'origine des produits et de savoir avec qui revoir les arrangements. 

SELECT
    F.Societe,
    P.NomProd,
    Pa.PaysFR,
    ROUND(SUM(DC.Quantité * P.CoutAchat * C.CoefMarge * (1 - DC.[Remise (%)])), 2) AS CA,
    ROUND(SUM(DC.Quantité * P.CoutAchat * (C.CoefMarge * (1 - DC.[Remise (%)]) - 1)), 2) AS Marge
FROM Categorie AS C
    INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
    INNER JOIN Fournisseur AS F ON P.NoFour = F.NoFour
    INNER JOIN DetailCommande AS DC ON P.RefProd = DC.[Réf produit]
    INNER JOIN Pays AS Pa ON F.NoPays = Pa.NoPays
WHERE
    Pa.UE LIKE "MEMBRE"
GROUP BY
    F.Societe,
    P.NomProd,
    Pa.PaysFR
ORDER BY
    CA DESC;

Requête 3 :

Dans le cadre d'une réflexion sur la santé, nous voulons connaître le chiffre d'affaires annuel généré par les catégories « Desserts » et « Boissons ».

Notre réflexion

L'intérêt de voir le CA annuel des desserts ou boissons est de repérer les produits mauvais pour la santé consommés de manière régulière et en grandes quantités, afin d'agir en fonction des caractéristiques des produits.

Ce qu'on a fait

Pour réaliser cette requête, nous avons joint les tables Catégorie et Produit afin de sélectionner les desserts et les boissons et d'obtenir leur coefficient de marge, leur nom et leur coût. Nous avons ensuite joint les tables Fournisseur, DétailCommande et Commande pour récupérer les noms des fournisseurs, les quantités commandées, les remises et les dates des commandes. Nous avons regroupé les résultats par année de commande grâce à la fonction YEAR, ainsi que par nom de produit et nom de la société du fournisseur, puis nous les avons triés par année et par chiffre d'affaires décroissants grâce à DESC. Nous avons décidé d'afficher le nom du produit et celui de la société afin de pouvoir identifier rapidement le produit et son origine. Pour obtenir les résultats souhaités, nous avons utilisé les fonctions ROUND et SUM. ROUND permet d'afficher le résultat avec un nombre défini de chiffres après la virgule. Cela évite les problèmes d'affichage dans Access. La fonction SUM nous permet de calculer la somme des marges, qui correspondent à la différence entre le prix de vente et le coût d'achat. Ces résultats permettent de repérer les produits les plus vendus et les quantités achetées. Cela permet de savoir quel fournisseur contacter ou quels produits moins mettre en vente si l'on juge qu'ils nuisent à la santé des clients ou qu'ils sont trop commandés. 

SELECT
    YEAR(Co.DateCde) AS Années,
    F.Societe,
    P.NomProd,
    Round(sum(DC.Quantité * P.CoutAchat * C.CoefMarge * (1 - DC.[Remise (%)])), 2) AS CA,
    Round(sum(DC.Quantité), 2) AS Quantité_vendues
FROM
    (
        (
            (
        Categorie AS C
                INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
            )INNER JOIN Fournisseur AS F ON P.NoFour = F.NoFour
        )INNER JOIN DetailCommande AS DC ON P.RefProd = DC.[Réf produit]
    )INNER JOIN Commande AS Co ON DC.[N° commande] = Co.[N° commande]
WHERE
    C.NomCateg IN ("Desserts", "Boissons")
GROUP BY
    YEAR (Co.DateCde),
    F.Societe,
    P.NomProd
ORDER BY
    YEAR(Co.DateCde) DESC,
    4 DESC;

Requête 4 :

Dans le cadre d'une réflexion sur l'offre commerciale, nous voulons calculer le nombre de produits carnés qui ne sont actuellement pas commandés.

Notre réflexion

L'intérêt de repérer les viandes qui n'ont jamais été vendues est d'identifier les produits qui ne se vendent pas et de déterminer s'il faudrait en baisser le prix ou renégocier avec le fournisseur.

Ce qu'on a fait

Pour réaliser cette requête, nous avons joint les tables Catégorie, Produit et Fournisseur. Puis, nous avons filtré les données pour ne garder que les produits de la catégorie « Viandes » qui n'ont pas été commandés. Nous avons trié les résultats par nom de produit et affiché le nom du produit, la société du fournisseur et le prix arrondi à deux décimales. Nous avons créé deux sous-requêtes. La première reprend la même structure que la requête, mais compte le nombre de produits de la catégorie qui n'ont pas été vendus. Cela est fait grâce à COUNT(*), qui compte toutes les lignes de la sélection et projette le résultat sous le nom Nombre_non_vendus. La deuxième sous-requête suit le même principe, mais compte tous les produits de la catégorie « Viandes » et projette le résultat sous le nom Nombres_total. Nous pouvons ainsi comparer le nombre de produits de la catégorie « Viandes » qui n'ont pas été vendus à celui des produits vendus. Enfin, nous pouvons facilement voir l'origine des produits grâce à leur nom et à celui du fournisseur, puis renégocier le prix d'achat. 

SELECT
    P.NomProd,
    F.Societe,
    ROUND(P.CoutAchat * C.CoefMarge, 2) AS Prix,
    ( SELECT COUNT(*)
        FROM Produit AS P
            INNER JOIN Categorie AS C ON P.CodeCateg = C.CodeCateg
        WHERE C.NomCateg = "Viandes"
            AND P.RefProd NOT IN (
                SELECT DetailCommande.[Réf produit]
                FROM DetailCommande
            )
    ) AS Nombres_non_vendus,
    ( SELECT COUNT(*)
        FROM Produit AS P
            INNER JOIN Categorie AS C ON P.CodeCateg = C.CodeCateg
        WHERE C.NomCateg = "Viandes"
    ) AS Nombres_total
FROM (
    Categorie AS C
    INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
)
INNER JOIN Fournisseur AS F ON P.NoFour = F.NoFour
WHERE
    C.NomCateg = "Viandes"
    AND P.RefProd NOT IN (
        SELECT DetailCommande.[Réf produit]
        FROM DetailCommande
    )
ORDER BY
    P.NomProd;

Requête 5 :

Dans le cadre d'une réflexion sur les partenariats clients, les clients pilotes d'un réseau de partenaires passent-ils autant de commandes que leurs partenaires ?

Notre réflexion

L'intérêt de cette requête est de vérifier si les partenaires commandent autant que les clients. Cela permettrait à Kdou de savoir si ce modèle, où des clients en amènent d'autres, est intéressant ou non.

Ce qu'on a fait

Pour répondre à cette question, nous avons joint la table Clientele à elle-même à l'aide de l'identifiant du client et de celui de son partenaire. Puis, nous avons créé deux sous-requêtes dans la jointure. La première récupère le code client dans la table Commande et compte le nombre de commandes avec COUNT. Ensuite, nous l'associons à la première table Clientele, ce qui nous indique le nombre de commandes passées par les clients. Pour la deuxième sous-requête, nous faisons la même chose avec la seconde table Clientele, qui représente les partenaires. Cela permet de connaître le nombre de commandes passées par les partenaires. Enfin, nous filtrons les résultats pour ne garder que les cas où le nombre de commandes des clients est égal à celui de leurs partenaires. Pour l'affichage, nous trions par ordre alphabétique du nom du client et affichons son nom, son nombre de commandes, ainsi que le nom de son partenaire et le nombre de commandes de celui-ci. 

SELECT
    C1.Contact AS Client,
    Cclient.NB AS Client_commande,
    C2.Contact AS Partenaire,
    Cpartenaire.NB AS Partenaire_commande
FROM (
    (
        Clientele AS C1
        INNER JOIN Clientele AS C2 ON C1.CodeCli = C2.CodeCliPart
    )
    INNER JOIN (
        SELECT C.CodeCli, COUNT(C.[N° commande]) AS NB
        FROM Commande AS C
        GROUP BY C.CodeCli
    ) AS Cclient ON C1.CodeCli = Cclient.CodeCli
)
INNER JOIN (
    SELECT C.CodeCli, COUNT(C.[N° commande]) AS NB
    FROM Commande AS C
    GROUP BY C.CodeCli
) AS Cpartenaire ON C2.CodeCli = Cpartenaire.CodeCli
WHERE
    Cpartenaire.NB = Cclient.NB
ORDER BY
    C1.Contact;
