Requête 1e :

Quels fournisseurs proposent de la viande et du poisson ?

Notre réflexion

L'intérêt de cette requête est de trouver facilement les fournisseurs qui proposent deux types de protéines animales : le poisson et la viande.

Ce qu'on a fait

Pour réaliser cette requête, nous avons sélectionné la table Fournisseur, puis créé deux sous-requêtes. La première récupère les numéros des fournisseurs associés à des produits dont la catégorie contient le mot « poisson ». La deuxième fait la même chose pour les produits de la catégorie « viandes ». Enfin, nous avons trié les résultats par numéro de fournisseur et affiché toutes les colonnes de la table Fournisseur. 

SELECT
    F.*
FROM Fournisseur AS F
WHERE F.NoFour IN (
        SELECT P.NoFour
        FROM Produit AS P
            INNER JOIN Categorie ON Categorie.CodeCateg = P.CodeCateg
        WHERE Categorie.NomCateg LIKE "*Poisson*")
    AND F.NoFour IN (
        SELECT P.NoFour
        FROM Produit AS P
            INNER JOIN Categorie ON Categorie.CodeCateg = P.CodeCateg
        WHERE Categorie.NomCateg LIKE "*Viande*" )
ORDER BY
    F.NoFour;

Requête 1h :

Quels fournisseurs ne proposent que des desserts ?

Notre réflexion

L'intérêt de cette requête est de repérer les fournisseurs qui ne vendent que des desserts, car ces produits peuvent avoir un impact sur la santé des clients.

Ce qu'on a fait

Pour réaliser cette requête, nous avons utilisé la table Fournisseur et créé deux sous-requêtes. La première repère les fournisseurs qui proposent des produits n'appartenant pas à la catégorie « Desserts », s'il y en a, nous les excluons du résultat. La deuxième repère les fournisseurs qui proposent des produits de la catégorie « Desserts ». Enfin, nous avons trié les résultats par société et affiché le nom, le numéro et la ville du fournisseur afin de pouvoir l'identifier plus facilement. 

SELECT
    F.Societe,
    F.NoFour,
    F.Ville
FROM
    FournisseurAS F
WHERE
    F.NoFour NOT IN (
        SELECT
            P.NoFour
        FROM
            Categorie AS C
            INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
        WHERE
            C.NomCateg NOT LIKE "Desserts"
    )
   AND F.NoFour IN (
        SELECT
            P.NoFour
        FROM
            INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
    )
ORDER BY
    F.Societe;

Requête 2 :

Dans le cadre d'une réflexion sur l'origine des produits, nous voulons connaître le chiffre d'affaires total généré à ce jour par les fournisseurs de l'Union européenne.

Notre réflexion

L'intérêt d'analyser le CA des produits issus de fournisseurs de l'UE est de repérer les produits les plus rentables pour KDou. Cela permet également d'identifier les fournisseurs avec lesquels maintenir de bonnes relations et ceux avec qui des ajustements sont nécessaires.

Ce qu'on a fait

Pour réaliser cette requête, nous avons joint les tables Catégorie, Produit, Fournisseur, DétailCommande et Pays. Nous avons sélectionné les fournisseurs membres de l'Union européenne, puis nous avons regroupé les résultats par fournisseur, produit et pays d'origine. Nous avons ensuite trié les résultats par chiffre d'affaires décroissant et affiché la société du fournisseur, le nom du produit, le pays, le chiffre d'affaires et la marge. Le chiffre d'affaires est calculé à partir des quantités vendues, du coût d'achat, du coefficient de marge et de la remise. Et la marge est calculée par la vente moins le coût d'âchat et de la quantité. Ces résultats permettent de repérer les produits les plus vendus et d'examiner leur marge afin de déterminer si des changements sont nécessaires. 

SELECT
    F.Societe,
    P.NomProd,
    Pa.PaysFR,
    ROUND(SUM(DC.Quantité * P.CoutAchat * C.CoefMarge * (1 - DC.[Remise (%)])), 2) AS CA,
    ROUND(SUM(DC.Quantité * P.CoutAchat * (C.CoefMarge * (1 - DC.[Remise (%)]) - 1)), 2) AS Marge
FROM Categorie AS C
    INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
    INNER JOIN Fournisseur AS F ON P.NoFour = F.NoFour
    INNER JOIN DetailCommande AS DC ON P.RefProd = DC.[Réf produit]
    INNER JOIN Pays AS Pa ON F.NoPays = Pa.NoPays
WHERE
    Pa.UE LIKE "MEMBRE"
GROUP BY
    F.Societe,
    P.NomProd,
    Pa.PaysFR
ORDER BY
    CA DESC;

Requête 3 :

Dans le cadre d'une réflexion sur la santé, nous voulons connaître le chiffre d'affaires annuel généré par les catégories « Desserts » et « Boissons ».

Notre réflexion

L'intérêt de voir le CA annuel des desserts ou boissons est de repérer les produits mauvais pour la santé consommés de manière régulière et en grandes quantités, afin d'agir en fonction des caractéristiques des produits.

Ce qu'on a fait

Pour réaliser cette requête, nous avons joint les tables Catégorie et Produit afin de sélectionner les desserts et les boissons et d'obtenir leur coefficient de marge, leur nom et leur coût. Nous avons ensuite joint les tables Fournisseur, DétailCommande et Commande pour récupérer les noms des fournisseurs, les quantités commandées, les remises et les dates des commandes. Nous avons regroupé les résultats par année, produit et fournisseur, puis les avons triés par année et par chiffre d'affaires décroissants. Les fonctions SUM et ROUND permettent de calculer le chiffre d'affaires et de l'arrondir à deux décimales. Ces résultats permettent de repérer les produits les plus vendus et, si nécessaire, de savoir quel fournisseur contacter ou quels produits moins mettre en vente. 

SELECT
    YEAR(Co.DateCde) AS Années,
    F.Societe,
    P.NomProd,
    Round(sum(DC.Quantité * P.CoutAchat * C.CoefMarge * (1 - DC.[Remise (%)])), 2) AS CA,
    Round(sum(DC.Quantité), 2) AS Quantité_vendues
FROM
    (
        (
            (
        Categorie AS C
                INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
            )INNER JOIN Fournisseur AS F ON P.NoFour = F.NoFour
        )INNER JOIN DetailCommande AS DC ON P.RefProd = DC.[Réf produit]
    )INNER JOIN Commande AS Co ON DC.[N° commande] = Co.[N° commande]
WHERE
    C.NomCateg IN ("Desserts", "Boissons")
GROUP BY
    YEAR (Co.DateCde),
    F.Societe,
    P.NomProd
ORDER BY
    YEAR(Co.DateCde) DESC,
    4 DESC;

Requête 4 :

Dans le cadre d'une réflexion sur l'offre commerciale, nous voulons calculer le nombre de produits carnés qui ne sont actuellement pas commandés.

Notre réflexion

L'intérêt de repérer les viandes qui n'ont jamais été vendues est d'identifier les produits qui ne se vendent pas et de déterminer s'il faudrait en baisser le prix ou renégocier avec le fournisseur.

Ce qu'on a fait

Pour réaliser cette requête, nous avons joint les tables Catégorie, Produit et Fournisseur, puis sélectionné les produits de la catégorie « Viandes » qui n'apparaissent dans aucune commande. Nous avons trié les résultats par nom de produit et affiché le nom du produit, la société du fournisseur et le prix arrondi à deux décimales. Une sous-requête compte les produits carnés non vendus, tandis qu'une autre compte le nombre total de produits de cette catégorie. Nous pouvons ainsi comparer ces nombres et déterminer si les prix de certains produits doivent être revus. 

SELECT
    P.NomProd,
    F.Societe,
    ROUND(P.CoutAchat * C.CoefMarge, 2) AS Prix,
    ( SELECT COUNT(*)
        FROM Produit AS P
            INNER JOIN Categorie AS C ON P.CodeCateg = C.CodeCateg
        WHERE C.NomCateg = "Viandes"
            AND P.RefProd NOT IN (
                SELECT DetailCommande.[Réf produit]
                FROM DetailCommande
            )
    ) AS Nombres_non_vendus,
    ( SELECT COUNT(*)
        FROM Produit AS P
            INNER JOIN Categorie AS C ON P.CodeCateg = C.CodeCateg
        WHERE C.NomCateg = "Viandes"
    ) AS Nombres_total
FROM (
    Categorie AS C
    INNER JOIN Produit AS P ON C.CodeCateg = P.CodeCateg
)
INNER JOIN Fournisseur AS F ON P.NoFour = F.NoFour
WHERE
    C.NomCateg = "Viandes"
    AND P.RefProd NOT IN (
        SELECT DetailCommande.[Réf produit]
        FROM DetailCommande
    )
ORDER BY
    P.NomProd;

Requête 5 :

Dans le cadre d'une réflexion sur les partenariats clients, les clients pilotes d'un réseau de partenaires passent-ils autant de commandes que leurs partenaires ?

Notre réflexion

L'intérêt de cette requête est de vérifier si les partenaires commandent autant que les clients. Cela permettrait à Kdou de savoir si ce modèle, où des clients en amènent d'autres, est rentable ou non.

Ce qu'on a fait

Pour répondre à cette question, nous avons joint la table Client à elle-même à l'aide de l'identifiant du client et de celui de son partenaire. Nous avons ensuite créé une sous-requête qui compte les commandes de chaque client, puis associé ce résultat aux deux tables Client. Nous avons sélectionné les clients et leurs partenaires ayant passé le même nombre de commandes. Enfin, nous avons trié les résultats par nom de client et affiché le nom ainsi que le nombre de commandes de chacun.

SELECT
    C1.Contact AS Client,
    Cclient.NB AS Client_commande,
    C2.Contact AS Partenaire,
    Cpartenaire.NB AS Partenaire_commande
FROM (
    (
        Clientele AS C1
        INNER JOIN Clientele AS C2 ON C1.CodeCli = C2.CodeCliPart
    )
    INNER JOIN (
        SELECT C.CodeCli, COUNT(C.[N° commande]) AS NB
        FROM Commande AS C
        GROUP BY C.CodeCli
    ) AS Cclient ON C1.CodeCli = Cclient.CodeCli
)
INNER JOIN (
    SELECT C.CodeCli, COUNT(C.[N° commande]) AS NB
    FROM Commande AS C
    GROUP BY C.CodeCli
) AS Cpartenaire ON C2.CodeCli = Cpartenaire.CodeCli
WHERE
    Cpartenaire.NB = Cclient.NB
ORDER BY
    C1.Contact;
